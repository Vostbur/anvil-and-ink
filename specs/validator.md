# SPEC: Validator

## Роль

Единственный барьер между галлюцинацией и игроком. Сверяет ответ LLM с **манифестом** (тем, что нарратор видел), не с «истиной». Консервативен: лучше отклонить корректный ответ, чем пропустить галлюцинацию.

## Контракт

```
validate(response: str, manifest: Manifest) -> {ok: bool, reason: Reason | null}

Reason:
  code:    empty | too_short | too_long | mechanics_leak | unknown_number | unknown_name
  message: str   # человеческая фраза на языке наблюдаемых фактов (для заметки ретрая)
```

## Порядок проверок (жёсткий)

Первая сработавшая возвращает `reject`. Порядок отражает стоимость.

### 1. Пустота

- `response.strip() == ""` → `reject / empty`.

### 2. Длина

- `< 15 символов` → `reject / too_short`.
- `> 1000 символов` → `reject / too_long`.
- Количество предложений **не проверяется**.

### 3. Утечка механики

Grep по ответу:
- имена флагов из канона (`bunker_door_open`, `wounded_watered`, …);
- коды причин (`condition_not_met`, `invalid_combination`, …);
- служебные слова: `флаг`, `состояние`, `outcome`, `валидатор`, `манифест`.

Найдено → `reject / mechanics_leak`.

### 4. Числа

Извлечь все `\d+` из ответа. Каждое сверить с `manifest.allowed_numbers`. Число вне множества → `reject / unknown_number`.

Числительные прописью 1–10 по словарю (`один…десять`) — тоже сверяются. Больше 10 прописью — **игнорируются** (известное ограничение).

### 5. Имена

Источник — **глобальный список имён канона** (все локации, NPC, типы предметов, `use_targets`). Не «заглавные буквы».

Для каждого имени из канона:
- найти в ответе (точное → стемминг → fuzzy 90);
- если найдено и **не** в `manifest.allowed_names` → `reject / unknown_name`.

**Многословные имена** ищутся как фраза целиком (с учётом словоформ каждого слова). **Однословные** — по слову.

Стемминг — усечённый набор русских окончаний (`-а, -я, -ы, -и, -ов, -ев, -ой, -ый, -ая, -ое, -у, -ю, -е, -ом, -ем, -ах, -ях`). Fuzzy-порог 90.

Имена **вне канона** («эльф», «стражник») не проверяются — известное ограничение.

## Формат `reason`

- `code` — машинный, для лога/тестов/агрегации.
- `message` — человеческая фраза для заметки ретрая: «в ответе упомянуто имя „эльф“, которого не было в контексте», «в ответе упомянуто число 15, которого не было в произошедшем».

## Известные ограничения

- Имена вне канона не проверяются.
- Числительные >10 прописью не проверяются.
- Нарицательные NPC дают ложные срабатывания (лечится полем `name_is_common` в каноне, не в MVP).
- Смысловые ошибки («открыл запертую дверь») не ловятся.
- Стемминг — эвристика, не морфология.
