# SPEC: Parser

## Роль

Детерминированный переводчик с человеческого языка на язык движка. Принимает строку, возвращает `Command` (см. `ARCHITECTURE.md` §3.1). Не проверяет предусловия — это движок. Не формирует коды причин — это движок.

## Входные данные

- `raw: str` — сырая строка игрока.
- `canon` — словарь глаголов, направлений, имён сущностей, алиасов `use_targets`, тем NPC.
- `projection` — **только** для разрешения коллизий между пространствами имён (см. этап 4, шаг 3).
- `fuzzy_threshold: int = 85` — из конфига.

## Пайплайн (5 этапов)

### Этап 1. Нормализация

- Привести к нижнему регистру.
- Заменить `ё` → `е`.
- Удалить знаки препинания (кроме дефисов внутри слов).
- Схлопнуть пробелы, обрезать края.
- Разбить на токены по пробелам.

Никакой лемматизации. Падежи разбираются нечётким сравнением на этапе 4.

### Этап 2. Определение глагола (longest match)

Идти по началу строки, сопоставляя **самый длинный** алиас из `canon.verbs`:
- сначала двухтокенные алиасы, потом однотокенные;
- внутри одного глагола дубликаты безвредны.

Если ни один алиас не совпал → `Command{verb: UNKNOWN, raw: raw}`, разбор завершён.

Глагол всегда стоит в начале. «Фильтр взять» → `UNKNOWN`.

### Этап 3. Извлечение аргументов по шаблону глагола

Для каждого глагола — свой способ. Везде: «фраза цели» — остаток строки, разрешаемый на этапе 4.

- **LOOK** — аргументов нет; всё после глагола игнорируется.
- **GO** — один аргумент `direction`: остаток строки → алиасы направлений (longest match).
- **TAKE / DROP** — один `item`: остаток строки целиком — фраза цели.
- **TALK** — два аргумента: `npc` и `topic`.
  - `npc`: ищется по имени в любом месте остатка (longest substring match по имени NPC из канона).
  - `topic`: ищется после предлога `{про, о, об, насчёт}` (всё после — кандидат в тему); если предлога нет — тема ищется независимо как отдельный токен, совпадающий с ключом темы какого-либо NPC.
  - Если NPC не найден — `npc=null, resolved.npc=false`. Если тема не найдена — аналогично.
- **USE** — два аргумента: `item` и `target`.
  - Если есть предлог `{на, к, с, об}`: всё до — кандидат в `item`, всё после — кандидат в `target`.
  - Если предлога нет: первый токен (или первая фраза, разрешаемая в предмет) — `item`, остаток — `target`. Порядок аргументов важен: «использовать дверь кодом» **не** разберётся (известное ограничение).

### Этап 4. Разрешение фраз в id

На вход — фраза (строка), тип аргумента. На выход — id или `null`.

| Тип | Пространство поиска |
|---|---|
| `direction` | `canon.directions` (по `id` через алиасы) |
| `item` | `canon.items` (по `name`) |
| `npc` | `canon.npcs` (по `name`) |
| `topic` | ключи тем всех NPC (строка) |
| `target` (USE) | `canon.use_targets` + `canon.npcs` + `canon.items`, приоритет: use_targets → npcs → items |

Алгоритм:

1. **Точное совпадение** нормализованной фразы с именем/алиасом. Найдено ровно одно — готово.
2. **Fuzzy** (порог `fuzzy_threshold`). Ровно один кандидат — готово.
3. **Разрешение неоднозначности** (только для `USE.target` — коллизия между пространствами имён):
   - приоритет пространства: `use_targets` → `npcs` → `items`;
   - внутри пространства при равенстве — тот, что присутствует в проекции (`items_here`, `npcs_here`, `use_targets_here`); если и это не разрешило — `null`, `resolved=false`.
4. **Фраза цели** — longest substring match: скользящее окно по словам фразы, самое длинное подслово, fuzzy-совпадающее с именем. «Ржавый фильтр» → «фильтр».

### Этап 5. Сборка `Command`

Заполнить `args` (id только если `resolved=true`), `resolved`, `raw`, `verb`. Вернуть.

## Таблица поведения

| Глагол | Аргументы | Поведение при `resolved=false` — в движке |
|---|---|---|
| LOOK | — | — |
| GO | `direction` | `no_exit` |
| TAKE | `item` | `no_item_here` |
| DROP | `item` | `not_in_inventory` |
| TALK | `npc`, `topic` | `no_npc_here` / `no_topic` |
| USE | `item`, `target` | `not_in_inventory` / `no_target` |
| UNKNOWN | — | `unknown` |

**Разные коды для одного `resolved=false` в зависимости от глагола — это дизайн, а не баг.**

## Известные ограничения

- Составные команды («взять X и идти Y») не поддерживаются как одна команда. `TAKE` возьмёт только `item`, остальное проигнорирует.
- Свободный порядок слов для `TAKE`/`DROP` не поддерживается («фильтр взять» → `UNKNOWN`).
- `USE` без предлога: порядок аргументов важен («использовать дверь кодом» не разберётся).
- Морфология — эвристика (стемминг + fuzzy), не полноценный анализатор.
- `LOOK` игнорирует аргумент: «осмотреть дверь» = «осмотреться».
