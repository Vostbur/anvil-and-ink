# SPEC: Game Session (orchestrator)

## Роль

Composition root. Единственное место, где встречаются все компоненты и задан порядок их вызовов. Сам по себе почти ничего не «делает» — упорядочивает.

## Контракт

```
start(config) -> Session
Session.step(raw: str) -> TurnResult
Session.save(path)
Session.load(path, config) -> Session
Session.history() -> [str]
```

`TurnResult` (см. `ARCHITECTURE.md` §3.4): `text`, `game_finished`, `aborted`, `abort_reason`.

## Полный цикл хода (12 шагов)

Порядок жёсткий.

1. **Валидация ввода.** Пустая / >500 символов → трактуется как `UNKNOWN` (шаги 2–9 пропускаются, кроме записи `turn`-события).
2. **Парсер** → `Command`. Падение — `CRITICAL`, трактовка как `UNKNOWN`.
3. **Движок** → `Outcome`. Падение — `CRITICAL`, трактовка как `UNKNOWN`.
4. **Применение `Outcome.applied` к проекции.** Атомарно. Ошибка целостности → `aborted=true`, `CRITICAL`, сессия остановлена.
5. **Запись `kind: turn` в `session.jsonl`.** Ошибка записи → `aborted=true`, `CRITICAL`.
6. **Проверка `win_condition`.** Истинно → `game_finished=true` (но не остановка).
7. **`UNKNOWN`?** Да → `renderer.render` → `final_text`, `rung=null`, `skip_reason=unknown_command`. Шаги 8–9 пропущены.
8. **Сборщик промпта** → `(prompt, manifest)`. `BuildError` → шаг 10, `WARNING`, `fallback_reason=build_error`.
9. **Лестница** → `(final_text, rung, skip_reason, fallback_reason, diagnostics)`. Диагностика логируется.
10. **Рендеринг шаблона** (только если пришли сюда из 7, 8 или ступени 3 лестницы). Падение → заглушка ступени 4, `CRITICAL`.
11. **Запись `kind: presentation` в `session.jsonl`.** Ошибка записи → `WARNING`, текст всё равно отдаётся.
12. **Возврат `TurnResult`.** Если `game_finished` — цикл завершается после шага 11.

## Гарантии порядка (см. `ARCHITECTURE.md` §4)

1. Состояние меняется **до** вызова LLM (шаги 4–5 до 9).
2. `turn`-событие **до** вызова LLM (шаг 5 до 9).
3. Fallback всегда доступен (шаблоны провалидированы при загрузке).

## Два лога

**`session.jsonl`** (сейв): `kind: turn` (raw, command, outcome) + `kind: presentation` (final_text, rung). Две записи на ход.

**`diagnostic.jsonl`** (телеметрия): промпты, ответы, latency, вердикты валидатора, шаги лестницы. В сейв не входит.

## Save / Load

**Save:** копия `session.jsonl`.

**Load (replay):**
1. `state = build_initial(canon)`.
2. Проход по `kind: turn` записям в порядке `turn`; для каждой — `apply(state, outcome.applied)`.
3. `turn` = максимальный.
4. `game_finished` = проверка `win_condition` на восстановленной проекции (не из лога).
5. `presentation`-записи в replay не участвуют.

Replay **не вызывает движок и парсер**. Применяет `applied` напрямую.

## Режимы

- `no-llm`: клиент = `null` → лестница сразу ступень 3.
- `llm`: реальный клиент.
- `broken-llm`: мок с инжекцией отказов (детерминированный сценарий).

Режим — конфиг, не ветвление в сессии.

## Отказы

| Шаг | Штатный исход | Деградация | Фатально |
|---|---|---|---|
| 1 | проходит | пусто/длинно → `UNKNOWN` | — |
| 2 | `Command` | падение → `CRITICAL`, `UNKNOWN` | — |
| 3 | `Outcome` | падение → `CRITICAL`, `UNKNOWN` | — |
| 4 | новая проекция | — | ошибка целостности → `aborted` |
| 5 | записано | — | ошибка диска → `aborted` |
| 6 | проверено | — | — |
| 7 | шаблон | — | — |
| 8 | промпт+манифест | `BuildError` → шаблон, `WARNING` | — |
| 9 | `final_text` | ступени 2–4 = штатная деградация | — |
| 10 | текст | падение → заглушка, `CRITICAL` | — |
| 11 | записано | ошибка диска → `WARNING` | — |
| 12 | отдано | — | — |

| # | Сценарий | Ожидание |

## Известные ограничения

- `aborted` — единственный сценарий, когда сессия останавливается сама.
- `presentation` может отсутствовать для последнего хода при падении между 5 и 11 — корректное состояние лога.
- Сейв совместим с каноном, на котором создан.
