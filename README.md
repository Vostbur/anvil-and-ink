# anvil-and-ink

Текстовая приключенческая игра на архитектуре **«жёсткий движок + мягкий рассказчик»** (Уровень 1). Детерминированный движок — единственный источник истины о мире; LLM — только слой, который переводит факты в живую прозу. Игра проходима на шаблонах без единого вызова модели.

Первый сюжет — **«Последняя батарея»**: постапокалиптическая мини-игра о том, как достать код и открыть бункер. Три локации, два NPC, четыре типа предметов, шесть глаголов.

## Ключевые идеи (если читать некогда)

1. **Движок решает правду, LLM объясняет её.** LLM не может изменить состояние — она физически не имеет доступа к записи.
2. **Состояние — в event-логе, а не в промпте.** Промпт — проекция, генерируемая на каждом ходу.
3. **Fallback всегда доступен.** Игра проходима на шаблонах без единого вызова LLM.
4. **Состояние меняется до вызова LLM.** Падение модели не откатывает ход, не теряет действие игрока.
5. **Две записи на ход в `session.jsonl`:** `turn` (механическая истина) + `presentation` (что увидел игрок). `session.jsonl` — это и есть сейв.
6. **UNKNOWN никогда не идёт к LLM.** Мета-коммуникация — не проза.
7. **Максимум 2 вызова LLM на ход.** Отзывчивость важнее качества при сбое.

## Что дальше

Три возможных исхода после живой сессии (подробно — в `LIVE_SESSION_PROTOCOL.md`):

1. **Итерируем Уровень 1** — точечные правки канона, парсера, промпта; повтор сессии.
2. **LLM не оправдывает сложности** — возможно, для этой игры достаточно шаблонов + хорошего автора канона. Ценное открытие, не поражение.
3. **Переход к Уровню 2** — LLM предлагает изменения состояния в структурированном виде, движок валидирует и применяет. Снимает потолок свободы действий.

Какой путь выбрать — зависит от данных живой сессии, а не от плана. MVP существует, чтобы дать эти данные.
